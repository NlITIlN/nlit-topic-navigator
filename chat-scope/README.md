# Область тем чата

Исходная точка — чистый локальный `main` версии 1.8.1, коммит `d98880c635bf4939ecc404e636a547f521c78ab4`, дерево `749b074bdaaa4d9e7c9201b28aa4358e4c389778`. Публичный `main` на `d32d757c3dab1d9eb0c29c6dec11e0027b2d239f` имеет то же дерево при другой истории.

## Как работает срез

1. `topics_scope_diagnostics` читает только MCP `params._meta["openai/session"]` и возвращает отпечаток для пары «аутентифицированный владелец, значение сессии». Диагностика работает без базы.
2. После явного решения владельца `topics_scope_confirm({fingerprint, confirm:true})` регистрирует текущую пару. Запрос проверяет отпечаток заново. Повторное подтверждение сохраняет действующий каталог. Если значение сессии изменилось, обычные операции возвращают ошибку до отдельного подтверждения.
3. Все обычные операции, включая выбор, поиск, группы, дерево, историю, импорт, экспорт и журналы, используют только зарегистрированную область текущего запроса. При отсутствии контекста, в том числе на самостоятельной странице `/api/topics`, выдача тем недоступна.
4. По просьбе «покажи мою тему из другого чата по ID …» инструмент `topics_view_owned({id})` читает одну тему среди областей этого владельца. Для просмотра из нового чата достаточно корректного контекста MCP и входа владельца. Регистрация области нового чата не требуется. Если импорт сохранил один ID в двух областях, передай также `sourceFingerprint` из диагностики исходного чата. Инструмент возвращает карточку без записи в темы, ручные привязки, выбор или активность.

Владельца определяет существующий доверенный шлюз. Значение сессии служит маршрутизации внутри его каталога. Само по себе оно не удостоверяет чат. Владелец, управляющий запросом, может воспроизвести свою метаинформацию. Проверка отпечатка при подтверждении защищает от случайного подтверждения другого текущего значения. Владелец проверил сценарий одной беседы на Windows и iPhone. При изменении клиента или транспорта полезно повторить сравнение отпечатков.

## Данные и откат

Версия v2 использует отдельную `CHAT_DB`. Для новой тестовой базы применяют миграции из `drizzle/` по порядку до `0010_auto_topic_revision.sql` включительно. Миграция `0009` создаёт реестр чатов, а `0010` добавляет ревизию автоматической карточки. Отдельные SQL-файлы раннего прототипа повторно применять не требуется.

Для изучения исходной версии 1.8.1 используйте отдельный checkout публичного коммита `d32d757`. Та версия использовала другую привязку `DB`. При переключении исходника обе базы сохраняются раздельно. Миграция старого каталога отложена.

## Проверка

`node tests-chat-scope.mjs` запускает HTTP-обработчик и панель на фикстурах в памяти. `node tests-auto-topics-d1.mjs` проверяет миграции и параллельные записи на временной D1. См. [результаты в клиентах и оставшиеся сценарии](conversation-topics.md).
